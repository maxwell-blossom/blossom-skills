# Blossom Skills — V1 prototype (Greg, Nov 7 2026)

Live: https://blossom-skills.netlify.app (Netlify site `blossom-skills`, id fbc4d7b7-a267-451a-95a9-8c10121f0dd8). Last deploy 6aef69feb0f92d801f191b0c (v7, 1:35pm ET Nov 7).

Build: `python3 build.py` → `index.html` (single-page app, hash routes) + `skills/<slug>/SKILL.md` (served so the Claude Code / Cursor one-liners work).
Needs `assets/` next to build.py (unpack `assets.tgz`, then add anything newer): `_blossom_logo.png`, `logo_blossom_flower_256.jpg`, `beevis_avatar.svg`, `badge_verified_teal.svg`, `wall_tile.jpg`, `profiles/avatar_NN.jpg`, `brokers/*.png`, `fiscal_logo_96.png` (Fiscal's mark, used as the MCP tile — an MCP with a `logo` field in data.py shows that instead of its emoji).
Deploy tree = `index.html` + `skills/` + `shots/` (copy of `assets/shots/` — the sample-output screenshots; regenerate with `python3 gen_shots.py`, which renders Blossom-styled widgets with Playwright). Deploy via the Netlify MCP (deploy-site with the id above), verify live md5 == tree md5.

Catalogue and creators: `data.py`. Creators other than @blossom, @beevis, @maxstocks are invented. Downloads, ratings and reviews are seed numbers.

Decisions (Max, Nov 7): the page is framed as a tab inside the Blossom web app (mock sidebar with “Skills & MCPs” next to Chat with Beevis; no search bar or action icons in the top bar); broker MCPs are not listed on the MCPs tab — skills declare them under “Also supports”; required MCPs under “What it needs”; sample outputs are screenshots first (gallery + lightbox, first one on the card), text sample collapsed; creators can upload up to 4 screenshots; a skill can declare “⚠️ can place orders” (badge on card and listing) — the old “doesn’t place orders” check is gone; tagline “Built by verified investors on Blossom”; hero copy “Discover and download skills…to supercharge your investing.”; Connector MCP reads posts too (get_feed, get_ticker_posts, search_posts, get_post, get_my_posts). skills only can be posted (MCPs are listed by Blossom and partners); broker MCPs (Public, Questrade, Robinhood) listed as third-party with a ⚠️ can-place-orders badge; pricing = free / one-time / monthly / yearly, **no free trials**; Blossom take 20%; Blossom Aggregate Trade Data MCP is paid ($19/mo · $149/yr, no free tier); install tabs = Claude, Claude Code, Cursor, ChatGPT, Grok (Grok takes remote MCPs at grok.com/connectors → Custom; no skill files, so the tab says paste the SKILL.md as the first message).

Stripe: `PAYLINKS` at the top of the JS in build.py — one Payment Link (sandbox/test mode) per paid plan. null = the mock checkout opens. A real link gets `?client_reference_id=<handle>:<skill>:<plan>`; the Payment Link's after-payment redirect is `https://blossom-skills.netlify.app/?checkout=success&skill=<id>&plan=<plan>` and the page records the purchase and shows the install screen. Wired so far: `dividend-income-planner` monthly → https://buy.stripe.com/test_8x2aEZaUOazn4nR0fd8so00 (product "Dividend Income Planner — Monthly", CA$4.99/mo, plink_1UZDRPP5k27Xop2fEqsW91yC). To add the rest: Stripe sandbox → Payment links → New → product + recurring price → After payment → "Don't show confirmation page" → the redirect above → Create link → paste into PAYLINKS → rebuild.

What is mocked: login (you are @maxstocks), review queue, Stripe Connect onboarding, comments/ratings composer, follower counts, entitlement checks (a skill is a text file; real gating lives in the Blossom MCP). Everything the user clicks works end to end in the browser; "my" skills and purchases persist in localStorage.
